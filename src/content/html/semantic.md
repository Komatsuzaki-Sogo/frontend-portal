## レイアウトタグの使い分け

Webページの各パーツがどのような役割を持っているのかをブラウザや検索エンジンに正しく伝えるため、なんでも `<div>` や `<span>` で囲まず、意味に合った適切なレイアウトタグ（セマンティック要素）を使用してください。

### どういうときに使うか（選定基準）

* **`<header>` / `<footer>`:** ページ全体に共通するグローバルヘッダー・フッターだけでなく、ページ内の各ブロック（`<article>` や `<section>` など）の中の導入部や注釈にも使用できます。
* **`<main>`:** そのページの「主役」となるコンテンツ群を包む際に使用します。検索エンジンに対して不要な共通ナビゲーションなどを除外した「本文本体」の場所を明示する役割があります。
* **`<nav>`:** 主要なリンクの集まりに使用します。フッターの小さなコピーライト横のリンクなどには不要ですが、ヘッダーメニュー、サイドのカテゴリ一覧、パンくずリストなどは必ずこれで囲みます。
* **`<article>`:** そのパーツだけを切り取って「他のサイトやSNSにそのまま転載しても、単体で意味が100%通じる独立した塊（ブログ記事、ニュース、1件の口コミなど）」に使用します。
* **`<section>`:** articleほど独立していない、単なる「章」や「テーマごとの塊」に使用します。**内部にテーマを示す「見出し（h2〜h6）」が必ず含まれる場合にのみ使用する**のが最大の特徴です。見出しがない単なるデザイン目的のグループ化には `<div>` を使用してください。
* **`<aside>`:** 本文から逸れた補足情報、広告、サイドバーのプロフィールの表記などに使用します。

| タグ名                  | 役割と適切な使用シーン                                                                                 |
| :---------------------- | :----------------------------------------------------------------------------------------------------- |
| **`<header>`**  | ページ全体、または各セクションの導入部・ヘッダー（ロゴやナビゲーションなど）。                         |
| **`<main>`**    | ページの主要なメインコンテンツ（1ページ内に1つのみ配置可能）。                                         |
| **`<footer>`**  | ページ全体、または各セクションのフッター（著作権表記や関連リンクなど）。                               |
| **`<nav>`**     | 主要なナビゲーション（グローバルメニュー、パンくずリストなど）。                                       |
| **`<article>`** | ブログの記事、ニュース、投稿など、それ単体で独立して完結しているコンテンツ。                           |
| **`<section>`** | 一般的なセクション（章やテーマごとの塊）。**原則として内部に必ず見出しを含める必要があります。** |
| **`<aside>`**   | メインコンテンツと間接的な関係しか持たないサイドバーや補足情報。                                       |

```html
<header>
  <h1>サイトロゴ</h1>
  <nav>ナビゲーション</nav>
</header>
<main>
  <article>
    <h2>記事タイトル</h2>
    <section>
      <h3>章の見出し</h3>
      <p>本文テキスト本文テキスト</p>
    </section>
  </article>
</main>
<footer>
  <small>© 2026 〇〇 Inc.</small>
</footer>
```

## 見出しタグ（h1〜h6）のルール

見出しタグは、ページの目次を作るための重要な要素です。視覚的なデザイン（文字の大きさ）の都合でタグを選んではいけません。

- 文書構造の順番通りに使う：`<h1>`の次には `<h2>`、その次には `<h3>`と段階的に使用し、途中の番号を飛ばして使ってはいけません（例:`<h2>`の次に `<h4>`を使うのはNG）。
- `<h1>`は原則として1ページに1つ：ページの最上位見出しとして、メインコンテンツのタイトル等に1つだけ配置します。
- **共通コンポーネントとして作成する際に必ずタグを変更できるようにしてください。（[Polymorphic Components](https://belonginc.dev/members/ryo/posts/polymorphic-components/)）**

```html
<h1>h1見出し</h1>
<p>本文テキスト</p>
<h2>h2見出し</h2>
<p>本文テキスト</p>
<h3>h3見出し</h3>
<p>本文テキスト</p>
<h4>h4見出し</h4>
<p>本文テキスト</p>
<h5>h5見出し</h5>
<p>本文テキスト</p>
<h6>h6見出し</h6>
<p>本文テキスト</p>
```

## テキスト強調タグ（b / i / strong / em）の使い分け

HTMLでは、テキストの一部を目立たせるために複数のタグが用意されています。これらは見た目（太字や斜体）だけで選ぶのではなく、**「その文章が持つ意味や重要度」** に合わせて厳格に使い分けてください。

| タグ名                 | ブラウザの見た目 | 本質的な意味（使い分けの基準）                                                                  | 適切な使用シーンの例                       |
| :--------------------- | :--------------- | :---------------------------------------------------------------------------------------------- | :----------------------------------------- |
| **`<strong>`** | **太字**   | **極めて重要・緊急・警告**な内容。`<br>`（そこだけ読めば要点が伝わる部分）              | 警告文、製品の最重要メリット、締切日       |
| **`<b>`**      | **太字**   | 意味的な重要性はないが、 **実用的な目的で他と区別（注意を喚起）** したい部分。                    | 記事のリード文、文書内のキーワード、製品名 |
| **`<em>`**     | *斜体*         | 話し言葉における「**アクセント（強調）**」。`<br>`（イントネーションを変えて読ませたい部分） | 感情の強調、誤解を防ぐための念押し         |
| **`<i>`**      | *斜体*         | 意味的な強調ではなく、**技術用語や他国語、心情**など、文脈が他と異なる部分。              | 学名、専門用語、小説での登場人物の心の声   |

* **デザイン目的でのタグ選定は禁止：**\
  「太字にしたいからとりあえず `<strong>` を使う」「斜体にしたいから `<i>` を使う」といった、見た目（スタイル）を理由にしたマークアップは行わないでください。見た目のコントロールはすべてCSS（`font-weight` や `font-style`）で制御します。
* **`<strong>` の多用禁止：**\
  1つのページ、あるいは1つの文章内に `<strong>` が多すぎると、検索エンジンやスクリーンリーダーが「どこが本当に重要なのか」を判別できなくなります。ピンポイントでの使用を徹底してください。

### コード例と適切なユースケース

#### 1. `<strong>`と `<b>`の違い（太字系）

```html
<p><strong>注意：</strong> 濡れた手でプラグを絶対に触らないでください。</p>

<p>当社の最新製品である <b>アイポータル・プロ</b> は、社内DXを加速させるツールです。</p>
```

#### 2. `<em>`と `<i>`の違い（斜体・イタリック系）

```html
<p>私はそのシステムが <em>本当に</em> 必要なのです。</p>

<p>Web制作において、マークアップの正確性を示す概念を <i lang="en">semantics</i> と呼びます。</p>
```

## a要素とbutton要素の使い分け

Webサイトやアプリケーションに配置するボタンやリンクを実装する際、見た目が同じデザインであっても、**「クリックしたときに何が起きるか（挙動）」** に合わせて `<a>` 要素と `<button>` 要素を厳格に使い分けてください。

見た目がボタンのデザインだからといって、すべてを `<button>`（または `<a>`）で統一してはいけません。

### 使い分けの判断基準

判断に迷ったときは、そのボタンを押したときの挙動が「移動」なのか「アクション」なのかで決定します。

| 要素名                      | 本質的な役割                 | クリック時の具体的な挙動の目安                                                                                                                                                                                                 |
| :-------------------------- | :--------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`<a>` 要素**      | **ページの遷移・移動** | ・別タブや別ウィンドウで新しいページを開く`<br>`・同じページ内の別の場所（アンカー）へスクロールする`<br>`・PDFなどのファイルを開く（またはダウンロードする）                                                              |
| **`<button>` 要素** | **画面内の操作・実行** | ・モーダルウィンドウやポップアップを開閉する`<br>`・アコーディオン（折りたたみ）メニューを開閉する`<br>`・フォームの入力内容を送信（submit）する`<br>`・お気に入り登録やカート追加など、非同期（Ajax）でデータを処理する |

---

### 運用ルール

* **役割の混同禁止：**\
  「画面内のポップアップを開く」ために `<a>` 要素を使用したり、「別ページへリンクする」ために `<button>` 要素を使用したりしてはいけません。
* **href属性の不正利用禁止：**\
  `<a>` 要素をボタン用途として使うために、`href="#"` や `href="javascript:void(0)"` といったダミーの値を記述して JavaScript のイベントを設定する実装は完全に禁止（NG）とします。
* **button要素のtype属性明記：**\
  `<button>` 要素を使用する際は、ブラウザによるデフォルト挙動のバグを防ぐため、**必ず `type` 属性（`type="button"` または `type="submit"`）を明記**してください。

### コード例と適切なユースケース

#### 1. `<a>` 要素（リンク）の適切な使い方

```html
<a href="/company/about/">会社概要を見る</a>
<a href="#contact-form">お問い合わせへ進む</a>
<a href="#" class="js-modal-trigger">ログイン画面を開く</a>
```

#### 2. `<button>` 要素（ボタン）の適切な使い方

```html
<button type="button" class="js-modal-trigger">ログイン画面を開く</button>
<button type="submit">送信する</button>
```

## ul要素とol要素の使い分け

箇条書き（リスト）をマークアップする際、そのリストの「**順番（前後関係）に意味があるかどうか**」に合わせて、`<ul>` 要素と `<ol>` 要素を厳格に使い分けてください。

画面上のデザインで数字が出ているか、中黒（・）が出ているかといった「見た目」を基準にしてタグを選んではいけません。

### 使い分けの判断基準（早見表）

判断に迷ったときは、リストの「中身を入れ替えても意味が通じるか」を基準に決定します。

| 要素名                  | 正式名称       | 本質的な役割（使い分けの基準）                                                           | 適切な使用シーンの例                                                                       |
| :---------------------- | :------------- | :--------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------- |
| **`<ul>` 要素** | Unordered List | **順序に関係がない**リスト。`<br>`（項目を入れ替えても意味が通じるもの）         | ・製品の特長、メリット一覧`<br>`・ナビゲーションメニュー`<br>`・新着情報、お知らせ一覧 |
| **`<ol>` 要素** | Ordered List   | **順序に明確な意味がある**リスト。`<br>`（項目を入れ替えると意味が破綻するもの） | ・操作手順、業務のステップ`<br>`・ランキング（順位）`<br>`・道順、レシピの工程         |

* **直下の子要素の制限：**\
  `<ul>` および `<ol>` の**直下（1階層下）に配置できる要素は `<li>` 要素のみ**です。`<div>` や `<a>` などを直下に配置してはいけません。
* **デザイン（見た目）目的の選定禁止：**\
  「数字を表示させたいから `<ol>` を使う」「ポッチ（・）を表示させたいから `<ul>` を使う」というアプローチは禁止です。リストの先頭のマークは、CSSの `list-style-type` プロパティで自由にコントロールしてください。

### コード例と適切なユースケース

#### 1. `<ul>` 要素（順序なしリスト）の適切な使い方

```html
<h3>当社のツールの特長</h3>
<ul>
  <li>初期費用が0円で始められる</li>
  <li>直感的な操作で誰でも使いやすい</li>
  <li>24時間365日のサポート体制</li>
</ul>
```

#### 2. `<ol>` 要素（順序付きリスト）の適切な使い方

```html
<h3>アカウント登録の手順</h3>
<ol>
  <li>メールアドレスを入力して送信する</li>
  <li>届いたメールのURLをクリックする</li>
  <li>パスワードを設定して登録完了</li>
</ol>
```

## 定義リスト（`dl` / `dt` / `dd`）の使いどころ

`<dl>` は「Description List（説明リスト）」の略であり、ある「項目・言葉（`<dt>`）」と、それに対する「説明・値（`<dd>`）」のペアをグループ化して表すための要素です。独立した単一の情報を並べる際に使用します。

- 名前と値のペアへの適用：\
「よくある質問（Q&A）」や「新着情報（日付とタイトル）」、「会社概要（項目とステータス）」など、明確に1対1（または1対多）の関係性を持つデータの羅列に使用してください。
- 直下の子要素の制限：\
  HTML5の仕様上、`<dl>` の直下（1階層下）に配置できる要素は、`<dt>`, `<dd>`, およびスタイリング目的の `<div>` のみです。その他の要素（`<span>` や `<p>` など）を直下に配置してはいけません。
- ペアの柔軟性：\
  「1つの `<dt>` に対して複数の `<dd>`」や、「複数の `<dt>` に対して1つの `<dd>`」という構造は認められています。ただし、関係性が崩れるような不規則な並び順にしてはいけません。

```html
<dl>
  <div class="faq-item">
    <dt>Q. 支払い方法は何がありますか？</dt>
    <dd>A. クレジットカード決済、銀行振込、コンビニ決済に対応しています。</dd>
  </div>
</dl>
```

## 表（テーブル）の実装ルール

`<table>` は、縦軸（列）と横軸（行）の交点（マトリクス構造）によって情報が意味を持つ「2次元の表データ」を表すための要素です。複数の項目を網羅的に比較・確認する画面において使用します。

* **見出し要素（`<th>`）の必須化：**\
  表組みを実装する際は、その行や列が何を表しているかを示す **`<th>`（表見出し）要素を必ず記述** してください。すべてを `<td>`（表データ）だけで構成してはいけません。
* **レイアウト目的の使用禁止：**\
  CSSが普及していなかった時代の「テーブルレイアウト（画面の配置やデザインを制御するためだけに table タグを組む古い手法）」は完全に禁止です。必ず「表データ」として扱うべきコンテンツにのみ使用してください。
* **構造の明確化：**\
  表のタイトルを表す `<caption>` や、構造を明確にする `<thead>`, `<tbody>` などの識別タグを適切に使用して、コードの可読性とデータ構造を高めてください。

縦（プラン名）と横（項目）を比較するマトリクス構造のため `<table>` 要素が適切です。見出し（`<th>`）とデータ（`<td>`）が明確に区別されています。

```html
<table>
  <caption>料金プラン比較表</caption>
  <thead>
    <tr>
      <th>プラン名</th>
      <th>月額料金</th>
      <th>ストレージ</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th>ライト</th>
      <td>980円</td>
      <td>10GB</td>
    </tr>
    <tr>
      <th>プロ</th>
      <td>2,980円</td>
      <td>100GB</td>
    </tr>
  </tbody>
</table>
```

## 画像要素（img）の適切な使い方

`<img>` は、Webページ内に画像を埋め込むための要素です。画像の表示速度（パフォーマンス）、ページのレイアウトの安定性、および視覚障害者向けのアクセシビリティを担保するため、以下のルールを厳格に守って実装してください。

* **`alt` 属性の必須化：**\
   すべての `<img>` タグに必ず `alt` 属性を記述してください。画像が表示されない環境や、スクリーンリーダーによる音声読み上げ時に、画像の「代わりのテキスト」として機能します。
* **`width` / `height` 属性の明記：**\
   画像の元のサイズ（ピクセル数）を数値で必ず指定してください。属性値に単位（`px`）を書いてはいけません。
* **`loading="lazy"` による遅延読み込みの標準化：**\
   ページの初期読み込み速度を向上させるため、原則として画像には `loading="lazy"` を指定します。ただし、**ファーストビュー（ページを開いて最初に画面に入るエリア）に含まれる画像には指定してはいけません。**

```html
<img src="/assets/img/mv.jpg" alt="代替テキスト" width="1200" height="630">

<img src="/assets/img/img-01.jpg" alt="代替テキスト" width="600" height="400" loading="lazy">
```

### SPとPCでの画像切り替え（picture / source要素の活用）

スマートフォン（SP）用とパソコン（PC）用で全く異なる画像（トリミングやアスペクト比が異なる画像）へと切り替える（アートディレクションを行う）場合は、`display: none;` によるCSSでの切り替えは行わず、必ず **`<picture>` 要素と `<source>` 要素** を使用してください。

* **CSSでの非表示（display: none）による画像切り替えは原則禁止：**\
  CSSで画像を隠しても、ブラウザはHTMLに記述された `<img>` の画像データを裏で余計にダウンロードしてしまい、ユーザーの通信量（ギガ）とページの読み込み速度（パフォーマンス）を著しく悪化させます。
* **`<source>` 要素の `media` 属性（メディアクエリ）の明記：**\
  どの画面幅で画像を切り替えるかの基準（ブレイクポイント）を指定します（※プロジェクトの共通ブレイクポイントは「6. レスポンシブルール」に準拠してください）。
* **フォールバック用（基本）の `<img>` を必ず最後に記述する：**\
  `<picture>` タグの直下には、必ず最後に通常の `<img>` タグを配置してください。ブラウザは条件にマッチした `<source>` の内容を、この `<img>` タグに流し込んで表示します。これがないと画像自体が一切表示されません。

```html
<picture>
  <source media="(min-width: 768px)" srcset="/assets/img/img-pc.jpg" width="1200" height="500">

  <img src="/assets/img/img-sp.jpg" alt="代替テキスト" width="750" height="600">
</picture>
```
