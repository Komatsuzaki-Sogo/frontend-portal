## 次世代画像フォーマットの活用

Webページの容量の大部分を占める画像アセットは、見た目の美しさを維持したままファイルサイズを極限まで軽量化するため、適切な拡張子（フォーマット）を選択・書き出ししてください。

* **WebP（ウェッピー）への全面移行：**\
  写真やグラデーションを含むリッチな画像（従来の `JPEG` や `PNG`）は、すべて次世代フォーマットである `.webp` 形式に変換して書き出してください。画質をほぼ落とさずに、ファイル容量を 3割〜4割 削減できます。
* **ロゴやアイコンには SVG を使用する：**\
  色数の少ないロゴ、アイコン、単純なイラストなどは、すべてベクター形式の `.svg` で書き出してください。どれだけ拡大しても画像がぼやけず、テキストデータに近いため容量も極めて軽量です。

## レイアウトシフト（CLS）を防ぐ

画像が読み込まれた瞬間に、ページのコンテンツが「ガタッ」と不意に下にズレる現象（レイアウトシフト）は、著しくユーザー体験を損ね、SEO（Googleの評価指標である Core Web Vitals の CLS）に悪影響を与えます。

* 元のサイズ（アスペクト比）の数値を必ず明記する：\
すべての `<img>` タグには、その画像の元サイズのピクセル数を width と height 属性として必ず記述 してください。属性値に単位（px）を書いてはいけません。
* ブラウザによる領域の自動確保：\
これを記述しておくことで、ブラウザは画像データのダウンロードが完了する前であっても、正しいアスペクト比（縦横比）を計算し、画面内にあらかじめ「画像の表示スペース（プレースホルダー）」を確保するため、ガタつきが 100% 発生しなくなります。

## loading="lazy"による遅延読み込みの最適化

ページを開いた瞬間に、画面の下の方（スクロールしないと見えない領域）にある大量の画像を同時にダウンロードすることは、通信帯域を圧迫し、初期表示速度を著しく低下させます。

* ファーストビュー「外」の画像には `loading="lazy"` を付与：\
スクロールして初めて到達するような中段以降の画像には、すべて `loading="lazy"` 属性を付与してください。ブラウザは、その画像が画面に近づくまでダウンロードを自動的に後回しにします。
* ファーストビュー「内」の画像には絶対に付けない：\
ページを開いた瞬間に最初から画面に入っている画像（メインビジュアル、ヘッダーのロゴなど）に `loading="lazy"` を指定してはいけません。読み込み開始のタイミングがブラウザの判断により一歩遅れてしまい、初期表示（LCP指標）が低下します。

## CSS・JSファイルの圧縮

ソースコード内に含まれる「改行」「スペース」「インデント」「開発者向けのコメント」は、ブラウザがプログラムを実行する上では一切不要なデータであり、ファイル容量を無駄に増やす原因になります。

* 本番環境への配信時は「Minify（ミニファイ）」されたファイルを使用する：\
ビルドツール（Vite, Webpack, esbuild など）を通し、すべての不要な余白やコメントを完全に削ぎ落とし、変数名を短く最適化した圧縮版ファイル（例: main.min.css, bundle.js）を出力・配信してください。これだけでファイルサイズを数割〜半減させることができます。

## レンダリングをブロックしないJavaScriptの読み込み

ブラウザがHTMLのコードを上から順に解析（パース）している最中に、通常の `<script>` タグを発見すると、ブラウザはHTMLの解析をその場で完全にストップ（レンダリングブロック）し、JavaScriptファイルのダウンロードと実行を最優先で始めてしまいます。これが「ページを開いたときに一瞬白い画面のまま固まる」最大の原因です。

画面の描画を一切邪魔（ブロック）せずに、バックグラウンドで安全にJavaScriptを並行ダウンロードさせるため、スクリプトの読み込みには必ず `defer` 属性 または `type="module"` を指定してください。

* 通常の外部スクリプトを読み込む場合（defer）：\
`<script src="..." defer>` を指定します。HTMLの解析を止めずに裏で並行してダウンロードを行い、HTMLの解析がすべて完了した後に、記述された順番通りに安全に実行されます。
* TypeScriptのコンパイル後や、モダンなモジュールシステム（`import/export`）を使う場合（`type="module"`）：\
`<script src="..." type="module">` を指定します。`type="module"` を指定されたファイルは、自動的に `defer` と全く同じ「非同期・レンダリングブロックなし」の性質を持つ ため、これ単体でパフォーマンスが最適化されます。
* 読み込み位置の統一：\
以前のWeb制作で一般的だった「JQueryなどを動かすために `</body>` 直前にスクリプトタグを並べる」という古い手法は禁止します。`defer` または `type="module"` を付与した上で、すべてのスクリプトタグは `<head>` タグの内部に記述 してください。
