## ガイドライン運用フロー

### 新規追加

1. `src\content`の該当するカテゴリの中にmdファイルを追加
2. 以下の項目を**必ず**設定する
   1. `title`: タイトル
   2. `publishDate`: 公開日
   3. `category`: 単一カテゴリー
   4. `order`: カテゴリー内の表示する順番の制御

### 更新

1. `src\content`の該当するカテゴリの中にmdファイルを更新
2. `updatedDate`がない場合は追加、ある場合は更新する

## 新規カテゴリーを追加する場合

新規カテゴリーの場合は一覧ページやヘッダーナビで表示する順番を制御するために `/src/constants/categoryOrder.ts`の `CATEGORY_ORDER`を更新する

## コミットメッセージルール

Gitのコミット履歴（ログ）は、プロジェクトの「歴史書」であり、変更の背景を他の開発者が一目で理解するための重要なドキュメントです。当社の開発においては、メッセージの先頭に必ず変更内容の意図を表す **「プレフィックス（接頭辞）」** を付与するルールを標準化します。


| プレフィックス | 本質的な意味（使い分けの基準） | 具体的なユースケースの例 |
| :--- | :--- | :--- |
| **`feat`** | **新機能の追加** | 新しいコンポーネントの作成、新ページの追加、新しいロジックの実装 |
| **`fix`** | **バグ修正** | 表示崩れの修正、JavaScriptのエラー修正、リンク切れの対応 |
| **`refactor`** | **リファクタリング** | 挙動（機能）を変えずに、コードの可読性や構造を綺麗に整理・改善したとき |
| **`chore`** | **ビルド・設定関連** | npmパッケージのインストール・更新、ライブラリ設定ファイル（`tsconfig`、`vite` 等）の変更 |
| **`docs`** | **ドキュメントのみの変更** | `README.md` の修正、本ガイドライン（Markdownファイル）の更新、コード内コメントの追加・修正 |
| **`style`** | **フォーマット修正** | コードの意味（ロジック）に影響を与えない、空白・インデント・セミコロンの追加や修正 |
| **`test`** | **テストの追加・修正** | JestやVitestなどのテストコードの新規作成、既存テストのメンテナンス |
| **`remove`** | **ファイルの削除** | 使わなくなった古い画像、不要になったスクリプトやコンポーネントファイルの完全消去 |
